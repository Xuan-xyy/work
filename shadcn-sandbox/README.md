# 秋招 × 实习成长工作台（React 版）

React + TypeScript + Tailwind CSS v4 + shadcn/ui 实现。**与同目录的旧版零构建工作台（`../index.html`）共用同一份数据**——两边的 `localStorage` key 都是 `qiuzhao.workbench.v1`，在任一版本里改的记录，另一边刷新就能看到。

## 打开方式

**只想看效果 → 双击 `../秋招工作台.html`。**

那是一个 687 KB 的自包含单文件（IIFE + 内联 CSS/JS，零外部引用），不需要装任何东西、不需要服务器，拷到 U 盘或发微信都能直接打开。数据存在浏览器 localStorage 里，file:// 下已验证可正常持久化。

它是这样生成的：

```bash
pnpm build:single   # 生成 dist-single/ 再合成单文件
```

> **为什么不能直接双击 `dist/index.html`**：Vite 的入口是 `<script type="module">`，
> 而 file:// 页面的 origin 是 `null`，浏览器会以 CORS 为由拒绝加载模块脚本 —— 双击只会白屏。
> 所以单文件版改用 IIFE（普通 script），并把脚本挪到 `</body>` 之前。
> 这里有个坑：Vite 把入口脚本放在 `<head>`，模块脚本默认 defer 所以没问题，
> 但换成普通 script 后 defer 失效、会在 `<head>` 阶段立即执行，那时 `#root` 还不存在，
> React 挂载失败照样白屏。`scripts/inline.mjs` 里对此有断言，位置不对会直接构建失败。

## 运行（开发）

```bash
cd shadcn-sandbox
pnpm install
pnpm dev        # http://localhost:5173
```

其他命令：

```bash
pnpm typecheck    # tsc --noEmit（strict）
pnpm build        # typecheck + vite build（HTTP 部署用）
pnpm build:single # 单文件版，双击即开
pnpm preview      # 预览构建产物
pnpm kit:preview  # 把面试准备清单的 Markdown 产物写到 dist-kit/ 供人工核对
```

> `pnpm kit:preview` 是核对手段，不是给用户的功能：截图只能看到界面，
> 看不到复制/导出的那份 Markdown 到底长什么样。清单里的内容 bug
> （同一项目重复成卡片、软技能被当成技术问、层标题丢字）全都是靠它才发现的。

> `.npmrc` 里把 pnpm store 固定在项目内（`store-dir=E:/web/shadcn-sandbox/.pnpm-store`）。
> 这是为了在受限沙箱里也能装依赖；项目移到别处时删掉这一行即可。
> `package.json` 里的 `pnpm.onlyBuiltDependencies: ["esbuild"]` **不能删**——
> pnpm 10 默认拦截 esbuild 的构建脚本，删掉后 `vite build` 会失败。

## 视觉设计

**当前主题叫「藕荷」**：柔和粉紫 + 玻璃拟态 + 大圆角 + 衬线标题 + 左侧圆形图标导航轨，
画布上叠三团极淡的径向光晕（`.canvas-bloom`）。

> **这一版明确取代了第一版的设计指令。** 最初的规格是「白色、浅灰、Notion 蓝、
> 240px 文字侧栏、8px 圆角、禁用花哨配色」。后来用户给了参考图并要求「减少 AI 感、
> 按这个风格来，不用管冲突」——所以冲突处以参考图为准，本文档保留这段说明是为了
> 让后来的人知道**这是有意的覆盖，不是跑偏**。

「去 AI 感」具体做了这几件事：

1. **不用饱和的语义色**。`index.css` 在 `@theme` 里**重定义了 Tailwind 默认的
   `emerald / amber / rose / blue / violet / slate / zinc` 色阶**，用 `color-mix` 从单一基色
   推导整条 ramp（50–400 往白里调，600–950 往深锚色里压）。于是全站 60 多处
   `text-emerald-600`、`bg-amber-50` **不改一个类名**就整体降饱和了——默认那套鲜艳的
   绿/琥珀/玫瑰红正是「通用仪表盘」最主要的味道。
2. **删掉了彩虹色甜甜圈**。`Dashboard.tsx` 的 `STATUS_COLOR` 原本是硬编码的
   `#3b82f6 / #f59e0b / #8b5cf6 / #10b981 / #f43f5e`（蓝、琥珀、紫、翠绿、玫红），
   改成 `--stage-*` 令牌组成的同色系阶调，只留鼠尾草绿（Offer）和陶土红（已挂）当信号。
3. **KPI 从「一排同质小卡」改成「小字标签 + 衬线数字」**，并删掉与漏斗页脚重复的「响应率」，
   由 5 格减到 4 格。
4. **衬线只用在标题、字标和 KPI 数字上**（`--font-display`），正文仍是无衬线。
   字体栈全走系统字体（`Noto Serif SC → Songti SC → SimSun → Georgia`），**不引网络字体**——
   单文件版必须离线可用，这是硬约束。
5. **层次靠 backdrop-blur，不靠描边**。`.glass` = 半透明底 + `blur(22px) saturate(150%)`
   + 顶边内高光 + 极柔投影；卡片、对话框、抽屉、toast、输入框、下拉、tabs 全部统一，
   按钮一律药丸形（`rounded-full`）。
6. **导航轨按内容收缩并垂直居中**（`self-center`），不会在长页面上拉成一根几百像素空白的柱子。

### 三个核心闭环

**① 日报 → 亮点 → 简历（实习成长 + 简历素材）**
写日报时按「做了什么 / 卡点 / 做法 / 可量化结果」填，表单实时给出 0–100 素材质量分：
结果有数字 +40，任务写清 +15，行动 ≥25 字 +20、≥40 字再 +15，情境完整 +10。
点「提炼成亮点」生成 STAR 草稿，存库后可一键复制成简历句（动词开头 + 结果收尾）。
素材质量分是**按素材本身算的**，改完即时重算——不会停留在旧内容上。

**② 面试官会怎么追问（面试训练）**
「项目深挖」按一条日报生成三层追问，把日报里真实的卡点/做法/结果/技能注入模板，
所以问的是这条经历本身，不是通用题：
- 第 1 层 事实层 —— 你到底做了什么、边界在哪
- 第 2 层 决策层 —— 为什么这么选、备选和被否掉的理由
- 第 3 层 深挖层 —— 规模涨 10 倍哪里先垮、数字怎么测的、重做会改什么

复盘页把「问了什么」一行一题存下来，一键提取进题库；掌握度会决定下次复习时间
（没准备 +1 天 / 看过 +3 / 能说清 +7 / 经得住追问 +21）。
「准备清单」把这些合成为一份可带走的 Markdown（见下）。

**②′ 准备清单：把追问变成能带走的东西（面试训练）**
点「准备清单」（URL 是 `#/interview?kit=1`，可直接收藏）打开预览，可以复制全文或导出 `.md`：
1. **按项目聚合的三层追问**——同一项目写了多条日报会合并成一个项目块，追问去重；
   每道题都带「考什么」提示和一行留白的「我的答案」。
2. **复盘里踩过的坑**——只收「挂了」或写了「没答好」的复盘，顺利的面经没有复习价值。
3. **待复习题目**——按分类分组，带掌握度和到期日。
4. **技能证据速查**——技能 → 出现次数 → 能举哪个项目，面试官问「你熟悉 X 吗」时直接报项目名。
5. **反问环节**——单独一节，这部分最容易临场大脑空白。

生成器 `interviewKit.ts` 是纯函数（只读 DB），预览、复制、导出读的是同一次结果，
不会出现「预览和导出不一致」。

**③ 投哪个岗位挑哪几条（简历素材 + Offer 决策）**
JD 匹配按三层抽关键词：中文技术词表扫描 → 英文 token → 2–6 字中文短语。
**中文没有空格，按标点切出来的是一整句而不是词，所以扫词表信噪比最高**——这个教训写在代码注释里了。
技术词命中权重 3、普通词 1，标题命中额外 +1；算出覆盖率并列出「JD 里有、你没有的」。
草稿的素材选择与顺序持久化在本地，刷新不丢，可导出 Markdown。

Offer 对比六维（薪资/成长/团队/城市/稳定性/兴趣）各打 1–5 分，权重可调。
总分 = 加权得分 ÷ **加权满分**——没打分的维度不进分母，不会因为漏填而虚低。

## 关于 CloudShader

`src/components/ui/cloud-shader.tsx` 原样保留，但**默认没有被任何页面引用**。
它是全屏动画 WebGL 蓝天云层。第一版设计想要「安静、克制、留白」的信息型界面，
所以没用它；换成藕荷主题后它更不合群了（蓝天和粉紫画布打架）。
要用的话建议只放在登录页或空态整屏背景，并压低饱和度：

```tsx
<CloudShader skyTopColor="#f6e9ee" skyBottomColor="#fdf5f7" cloudColor="#ffffff" count={3} speed={0.4} />
```

## 已知限制

- **单文件 bundle 609 KB**（gzip 193 KB），构建时有 chunk 体积提醒。要优化就在 `vite.config.ts` 配 `manualChunks` 把 `radix-ui` 拆出去。
- 关键词抽取是词表 + 规则，不是分词器。遇到词表外的中文技术词会被漏掉，往 `CN_TECH` 里加即可。
- 语义色阶是**覆盖 Tailwind 默认家族名**实现的。往后再引入 shadcn 组件时，
  如果它用了本文档没覆盖的色阶档位（比如 `emerald-100`），会退回 Tailwind 默认值而显得突兀——
  往 `index.css` 的 `@theme` 里补一档即可。
- 数据只在浏览器本地，换电脑需要「导出备份 → 恢复备份」。

## 验证记录

- `tsc --noEmit`（strict）✅ 零报错；`vite build` ✅ 1733 模块
- 无头 Edge + SwiftShader 逐页截图核验（13 张，含每个 tab）✅

截图核验中发现并修掉的真实缺陷：

1. **`rel()` 被用在过去的日期上** —— 详情页把投递日期显示成「逾期 46 天」，日报显示「逾期 2 天」。加了 `ago()`，`rel()` 只留给截止日期。
2. **投递漏斗第一层用了「想投」** —— 得出「想投 23 · 100%」，可还没投出去的东西不该是漏斗的 100%。改为从「已投递」起算。
3. **演示数据全在 6 天前** —— 本周节奏恒为 0、周报全空、还误报「本周还没有新增投递」。加 `weekSlot` 按本周一动态定位。
4. **JD 关键词抽出的是整句话** —— 中文没有空格，按标点切出来的是「负责核心业务系统的后端服务设计与开发」而不是关键词，「缺失关键词」里全是「岗位职责」「至少」「一门语言」这类噪音。改为技术词表扫描 + 英文 token + 2–6 字短语，并过滤列表序号。
5. **素材质量分从日报算而不是从素材算** —— 改过的素材还挂着旧分数，编辑后分数根本不更新。加了 `scoreHighlight()`。
6. **题库 `reviewAt` 全部落在今天** —— 「待复习」等于题库总量（13/13），形同虚设。改为按掌握度排到未来，只剩真正逾期的 6 题。
7. **简历草稿的选择刷新就丢** —— 把选择与顺序一起持久化进 DB。
8. **单文件版仍然白屏** —— 内联脚本被 Vite 放在 `<head>` 里，`type="module"` 的 defer 语义在换成普通 script 后失效，脚本在 `#root` 之前执行导致 React 挂载失败。改为注入到 `</body>` 前并加断言。
9. **构建不可复现** —— `dist-single` 没写进 `.gitignore`，而 Tailwind v4 的自动源码探测遵守 `.gitignore`，于是它把上一次的产物当源码扫，CSS 在 61.73 kB 和 72.66 kB 之间漂移（多出 ~11 kB 死 CSS）。补上 `.gitignore` 后稳定在 61.73 kB，主构建 hash 也不再变化。
10. **页面标题还是脚手架遗留的** —— `<title>Cloud Shader · shadcn sandbox</title>`，改成「秋招 × 实习成长工作台」。

视觉改版（藕荷主题）与面试准备清单中发现的缺陷：

11. **甜甜圈是彩虹色的** —— `STATUS_COLOR` 硬编码了 `#3b82f6 / #f59e0b / #8b5cf6 / #10b981 / #f43f5e`。这是整站最重的 AI 感来源，改为 `--stage-*` 同色系阶调。
12. **准备清单把同一项目拆成重复卡片** —— 按日报展开，同一个项目写了两条日报就出现两张几乎一样的卡（追问模板是同一套）。改为**按项目聚合**：4 条日报合成 3 个项目，追问在同项目内去重，16 道降为 12 道。
13. **软技能被当成技术问** —— 生成了「这里用到了 Java / 项目推进 / SQL，讲讲最关键的那个特性」，对软技能是句废话。加 `techSkills()` 过滤，纯软技能的项目干脆不出这道题。
14. **清单弹窗的页脚被顶出可视区** —— `DialogContent` 是 `grid`，滚动区写的 `flex-1` 在 grid 容器里无效，内容把页脚挤出 `max-h` 之外。改为 `grid-rows-[auto_auto_minmax(0,1fr)_auto]`，页脚固定可见。
15. **三层追问的层标题丢了「事实层 / 决策层 / 深挖层」** —— `drillLayerLabel(l).split(" · ")[1]` 把前半截丢掉了，只剩「你到底做了什么」。改用完整标签。
16. **导航轨垂直居中后字标与首项之间出现大片留白** —— 改回顶对齐；最终整体改为「按内容收缩 + `self-center`」，从根上消掉长页面里的空白柱。

> 第 12–15 条是用 esbuild 把 `interviewKit.ts` 单独 bundle 出来、在 Node 里跑真实演示数据打印产物核对的
> （截图看不到导出内容）。这个核对手段保留成了 `pnpm kit:preview`。
